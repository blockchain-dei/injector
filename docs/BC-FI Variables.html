Variables

Observed

 Common

  tx_id

   the unique ID of the transaction

  request_type

   "transaction" or "query"

 Timestamps

  time_create

   the Unix epoch when the transaction was initiated

  time_endorse

   the Unix epoch when Caliper received the proposal responses from the endorsers

  time_orderer_ack

   the Unix epoch when Caliper received the confirmation from the orderer that it successfully received the transaction

  time_final

   the Unix epoch when the adapter received a successful commit event from 100% of the peers

  commit_success_{peer}

   the Unix epoch when the adapter received a successful commit event from {peer}

 Durations

  duration_ns_evm_{peer}

   The time it took in ns to execute the EVM bytecode on {peer}

  duration_ns_cc_{peer}

   The time it took in ns to execute the EVMCC proxy chaincode on {peer}

 Results

  status

   "failed" or "success"

  return_value

   the return value of the transaction/query

  endorsement_result_{peer}

   the chaincode invocation result returned by {peer}

  reads

   the sorted read entries in the read set in their canonical form: <namespace><key>@<block index>.<TX index>

  writes

   the sorted write entries in the write set in their canonical form: <namespace><key>@<hex-encoded value or null for delete>

 Error

  proposal_error

   the error message in case an error occurred during sending/waiting for the proposal responses from the endorsers

  proposal_response_error_{peer}

   The error message in case {peer} returned an error as endorsement result

  endorsement_verify_error_{peer}

   "INVALID" if the signature and identity of {peer} couldn’t be verified

  endorsement_result_error_{peer}

   the error message if the transaction proposal or query execution at {peer} results in an error

  read_write_set_error

   "MISMATCH" if the sent transaction proposals resulted in different read/write sets

  broadcast_error_{orderer}

   the warning message in case Caliper did not receive a successful confirmation from {orderer}

  broadcast_response_error_{orderer}

   the error message in case the adapter received an explicit unsuccessful response from {orderer}

  unexpected_error

   the error message in case some unexpected error occurred during the life-cycle of a transaction

  commit_timeout_{peer}

   has the value of "TIMEOUT" in case the event notification about the transaction did not arrive in time from {peer}

  commit_error_{peer}

   contains the error code in case the transaction validation fails at the end of its life-cycle on {peer}

  event_hub_error_{peer}

   the error message in case some event hub connection-related error occurs with {peer}

 Workload

  input_{i}

   The ith input of the transaction

  tx_index

   the index of the transaction in a single contract measurement (i.e., contract-level sequential transaction ID)

  function_name

   the invoked function of the Solidity contract

  load_generator_idx

   the 0-based index of the client process that generated the TX

 Contract Info

  contract_id

   the numeric ID of the contract

  reference_contract

   the ID of the non-faulty version of the contract

  contract_name

   the target contract of the transaction (e.g., BecToken-0-0)

  contract_classname

   the name of the target Solidity contract/class in the source code (e.g., BecToken)

Derived

 Durations

  duration_ms_total

   client-to-client total TX time in ms

  duration_ms_order_and_validate

   duration_ms_total - duration_ms_endorse (i.e., the ordering and validation time in ms)

 Checks

  faulty_contract

   true if the corresponding contract has a fault injected

  matches_return_value

   true if this TX's return value matches the return value of the corresponding transaction of the correct contract

  matches_read_set

   true if this TX's read set matches the read set of the corresponding transaction of the correct contract

  matches_write_set

   true if this TX's write set matches the write set of the corresponding transaction of the correct contract

  matches_status

   true if this TX's status matches the status of the corresponding transaction of the correct contract

  matches_reference_tx

   true if this TX's every aspect matches the corresponding transaction of the correct contract (i.e., the AND relation of the other matches_* attributes)
